## 1. 요구사항 맵 (원문 항목 정리)

### 1. App 동작 관련

| ID | 제목 | 요지 |
|----|------|------|
| 1-1 | 사운드 알람 미동작 | Very Low / Low / High / Rapid Change / Signal Loss 시 사운드 미동작. Method 설정이 저장 후에도 반영 안 되는 것으로 추정. |
| 1-2 | Signal Loss 반복 주기 | Repeat(1min, 5min 등) 저장 후에도 **최초 1회만** 알람, 이후 반복 없음. |
| 1-3 | Quiet hours + 앱 종료 | Signal Loss Quiet Hours 설정 후, 해당 시간대에 신호 끊기면 **앱 종료** → 재실행 시 로그인 화면. Quiet hours여도 앱은 종료되면 안 됨. |
| 1-4 | Lock screen 배너 | 제안: 혈당 값 + 변화 방향 화살표 동시 표시. 현재: Last Reading 형식만. |
| 1-5 | 언어 | 영어 고정 → **한국어 선택** 추가 후 동작 확인. |
| 1-6 | 15일 만료 후 앱 동작 | 만료 안내 + 제거 가이드 + 신규 센서 연결 진입. 신규 플로우는 SC_01_01과 동일 단계(가이드→QR→Save&Sync→BT→Warm-Up 30분→메인). |
| 1-7 | 센서 연결 이슈 3건 | (1) 로그아웃 후 동일 MAC·다른 SN QR 스캔 시 Start/남은 일이 이전 SN 기준 유지. (2) 오프라인 가입 후 로그인 시 Last Update는 신규인데 Start/남은 일은 이전. (3) Disconnect 후에도 반복 연결 시도·Disconnect 미반영처럼 보임. |

### 2. 앱 로그인·데이터 관련

| ID | 제목 | 요지 |
|----|------|------|
| 2-1 | 로그인·데이터 저장 | Sign In / 오프라인 로그인·QR 측정 / 자동업로드(eqsn·sensorStartAt) / GUEST LOGIN / IngestQueue 테스트 계정 자동 로그인 **삭제 검토** / 로그아웃 후 자동 센서 연결 **불가** 확인 / 재설치 후 프로필·혈당 복구 **질문** 형태. 추가: 오프라인에서 미가입·비정상 이메일·임의 텍스트로도 로그인되는 문제. |
| 2-2 | 센서 측정 종료 | 15일 만료 후 안내문, 사용자/앱/센서 측 종료, BLE 끊김 시 알림·자동 재연결 등 **검증·기대 동작**이 한 줄로 혼재. |
| 2-3 | 센서 종료 화면(OK) | 만료 후 연결 해제, How to remove 가이드, 스크롤 후 OK → 메인. |

## 2. 명확하지 않은 요구사항 (클라리피케이션 필요)

아래는 **원문만으로는 구현 범위·성공 기준·우선순위를 단정하기 어려운 항목**입니다. 기획/검수 측 확인이 필요합니다.

### 2.1 알람·설정 (1-1, 1-2)

| 항목 | 불명확한 점 |
|------|-------------|
| **1-1 Method** | “Method 설정”이 **어느 화면의 어떤 필드**(알림 채널, 사운드 파일, 시스템 알람 vs 인앱 등)를 가리키는지 용어 정의 없음. |
| **1-1 적용 범위** | 다섯 유형 알람이 **동일 사운드**인지, 유형별로 **다른 사운드/볼륨**이 필요한지 없음. |
| **1-2 Repeat** | 반복 미적용이 **Signal Loss에만** 해당하는지, **Weak RSSI 동일 그룹(AR_01_06)** 전체인지 문서에 구분 없음. |
| **1-2 “최초 1회”** | 앱 재시작 후·Quiet hours 경과 후·재연결 후 **반복 타이머가 리셋되는지** 기대 동작 없음. |

### 2.2 Quiet hours·크래시 (1-3)

| 항목 | 불명확한 점 |
|------|-------------|
| **재현 조건** | OS/기기, Quiet hours 시간대, 신호 끊김 유형(비행기 모드/BLE 거리/센서 전원) 등 **재현 절차**가 없어 원인 분석 난이도 높음. |
| **기대 결과** | Quiet hours 중에는 **알람만 억제**인지, **배너/로그도 억제**인지, **재연결 시도도 멈출지** 없음. |

### 2.3 Lock screen 배너 (1-4)

| 항목 | 불명확한 점 |
|------|-------------|
| **화살표 기준** | 직전 측정값 대비인지, N분 트렌드인지, **첫 측정 시** 표시 규칙(화살표 없음/Flat 등) 없음. |
| **단위·로캘** | mg/dL·mmol 표기 및 **한국어 배너 문구** 필요 여부 없음. |

### 2.4 언어 (1-5)

| 항목 | 불명확한 점 |
|------|-------------|
| **범위** | “한국어 선택”이 **UI 문자열만**인지, **서버 에러 메시지**까지 포함인지. |
| **전략** | 영어 유지 + 한국어 추가인지, 추후 다국어 확장 전제인지. **기본 언어**(첫 설치 시) 명시 없음. |

### 2.5 15일 만료·플로우 (1-6, 2-2, 2-3)

| 항목 | 불명확한 점 |
|------|-------------|
| **만료 시각** | `sensorStartAt` 기준 **정확히 15일 후 00:00**인지, **15×24시간**인지, **시작 시각 + 15일 동일 시각**인지, 타임존(기기 로컬 vs UTC) 없음. |
| **“자체 연결 해제”** | BLE `disconnect`만인지, `cgms.last_mac` 삭제·`eqsn` 초기화까지 포함인지. |
| **1-6 vs 2-3** | 만료 직후 **만료 전용 화면(2-3)** 과 **신규 연결 플로우(1-6)** 진입 순서(먼저 가이드 vs 먼저 스캔) 통합 스토리보드 없음. |
| **2-2 한 줄** | “자동 알림이나 자동 재 연결 시도 되지 않기”가 **만료 후 필수 스펙**인지, **현재 검수에서 관측된 현상**인지 문장 구조상 구분 어려움. |
| **2-2 vs 앱 동작** | 일반 BLE 끊김 시 **자동 재연결**은 앱에 존재할 수 있어, 만료 후에만 재연결 금지인지 전역 금지인지 불명확. |

### 2.6 센서·계정 데이터 (1-7, 2-1)

| 항목 | 불명확한 점 |
|------|-------------|
| **1-7 동일 MAC·다른 SN** | 물리적으로 **다른 부착 센서**인지, **동일 하드웨어에 SN만 바꾼 테스트**인지에 따라 `sensorStartAt` 리셋 정책이 달라짐. |
| **1-7 데이터 병합** | 이전 SN 로컬/서버 혈당을 **새 SN으로 이관**할지, **분리 보관**할지 없음. |
| **2-1 자동업로드** | “성공여부?”만 있어 **성공 정의**(HTTP 200, 서버 저장 검증, 중복 TRID 등) 없음. |
| **2-1 재설치** | “프로필 및 이전 혈당 호출”이 **필수 요구**인지 **질문**인지 구분 없음. **서버에 보관 범위**(전 기간 vs N일) 없음. |
| **Remember Me** | 미동작이 **버그 수정**인지, **스펙 미구현**인지; 기대 동작(자격 증명 저장 범위, 생체 연계) 없음. |
| **오프라인 로그인** | 2-1 문제 사항은 **오프라인 시 로그인 차단** 요구로 읽히나, **필드 검증만** 할지 **서버 도달 필수**로 할지 정책 문서화 필요. |

### 2.7 IngestQueue / 게스트 (2-1)

| 항목 | 불명확한 점 |
|------|-------------|
| **삭제 후 대안** | 테스트 계정 자동 로그인 제거 시 **게스트 모드에서 서버 업로드 완전 비활성**인지, **별도 익명 API**인지 결정 필요. |

### 2.8 2-3 UI (원문 참조)

| 항목 | 불명확한 점 |
|------|-------------|
| **이미지** | “좌측의 이미지와 같이”, “우측의 이미지와 같이” **첨부 이미지/피그마 링크**가 본 md에 없음. |
| **OK 노출 조건** | 스크롤 **끝까지** 내려야 활성인지, 일정 비율만 내려도 되는지 없음. |

## 4. 권장 우선순위 (분석 의견)

1. **1-3** — 앱 종료·세션 초기화로 이어질 수 있어 **안정성 최우선**.  
2. **1-7 + 2-1(데이터/오프라인)** — 잘못된 계정·SN 표시는 **의료 앱 신뢰도**에 직결.  
3. **1-1, 1-2** — 알람 스펙 확정 후 연동 수정.  
4. **1-6, 2-3, 2-2** — 만료 시각·재연결 정책 **클라리파이 후** 화면·BLE 일괄 설계.  
5. **1-4, 1-5** — UI/로캘, 배너 기준 합의 후 구현.
