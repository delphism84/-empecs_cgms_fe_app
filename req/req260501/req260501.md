- **문서 ID:** req260501  
- **원본:** `req.md` (메일/테스트 메모), `CGM App 검수후 문제사항_260423.pptx` (Node+JSZip 텍스트 추출 후 검수자 관점으로 요구사항화)  
- **작성일:** 2026-05-03  

**시점·재검증 (보수적 해석):** 본 문서는 **4월 말 전후 검수·메모 시점**의 관찰을 옮긴 것이다. 이후 빌드에서 **이미 수정·완화되었을 수 있으므로**, 이슈 트래킹·우선순위 결정 시 **앱/서버 버전·재현 절차·최신 재현 여부**를 별도로 확인하는 것이 안전하다. 날짜·빌드 번호(예: 4/21, 4/23)는 **해당 시점 기준**으로만 해석한다.

### 1.5 확인된 이슈 목록 (번호 부여)

> 당시 테스트에서 관찰된 목록이다. **현재도 동일한지는 재현 테스트로 확인**한다.

1. **Warm-Up 중 알림 발생**
2. **앱 동작 딜레이:** 초기 다운로드 시에는 딜레이 없음 → 테스트 진행할수록 딜레이 심화
3. **Start Time 표시:** 최초 설치 후 첫 센서 스캔은 정상. **로그아웃 → 센서 재연결** 후 **21일(4/21) 정보로 표시**되는 문제
4. **갤러리 등 기본 앱 이동 후 복귀:** `[Syncing with server]` 후 기본 화면에서 **멈춤** → 앱 삭제·재설치로만 해결 (참조 동영상)
5. **Serial Number 미표시**
6. **Data Share 딜레이:** 초기 약 1분 이상 → 시간 경과 후 약 **5초** 수준으로 감소
7. **로그아웃 후 동일 계정 로그인:** 기존 센서 **자동 재연결 안 됨**, 수동 연결 필요, 이때 **다시 Warm-Up 진입**

### 1.6 기타

### 항목 6 보강 — Data Share 딜레이 (코드 조사, SC_07_01)

PPT **2-1** 요약: `[Share]` 직후 즉시가 아니라 **수십 초~1분 뒤** 시트, 사용하다 보면 **약 5초**로 줄어듦 / **설정 조작 중 뒤늦게** 시트 / **연속 터치 시** 시트가 **여러 번**.

#### SC 범위·진입 경로

| 구분 | 내용 |
|------|------|
| **검수·스키마상 SC** | **SC_07_01** 한 곳이 Data Share 화면으로 매핑됨 (`docs/cgms_schema.md`, qa-bot `SC_07_01` → `/sc/07/01`). |
| **실제 구현** | `Sc0701DataShareScreen` (`lib/presentation/onboarding/sc_07_01_data_share_screen.dart`). Sensor 메뉴·리포트 등은 `Navigator.pushNamed('/sc/07/01')`로 이 화면만 사용. |
| **기타** | ~~`SensorSharePage`(미사용 축약본)~~ **삭제됨** — Data Share는 **`Sc0701DataShareScreen`(`/sc/07/01`)만** 유지. |

#### 지연의 앱 측 원인 (`_share()` 흐름)

공유 버튼은 **진행 모달 뒤** 아래를 **`await` 체인**으로 처리한 뒤 `Share.shareXFiles`를 호출한다.

1. **`_saveEvidence`** — `SettingsStorage` 읽기·쓰기 (상대적으로 짧음).
2. **`getApplicationDocumentsDirectory()`** — I/O.
3. 혈당 포함 시 **로컬 `range` 먼저** → 비어 있을 때만 **`fetchGlucose(..., skipLocalCache: false)`**로 서버 보강·재조회 (`api_client.dart`). (과거) 매번 `skipLocalCache: true`였을 때는 **매 요청 서버 GET**으로 **수십 초~1분대**가 나기 쉬웠음.
4. **`_loadGlucoseRowsForRange`** — SQLite (`limit: 200000`). 대량이면 추가 비용.
5. **PDF** — `MultiPage`·`doc.save()`·`writeAsBytes` — CPU 집약.
6. **`Share.shareXFiles`** — OS 공유 시트(제조사 편차).

**「처음은 길고 나중에 ~5초」**와 맞물리는 요인(추정): 첫 공유 시 **콜드 스타트**(TLS·첫 페이로드·대량 insert), 이후에는 **HTTP 연결 재사용·로컬 DB 히트**로 체감이 짧아질 수 있음. (적용 후) 로컬에 기간 내 데이터가 있으면 **서버 재조회를 생략**하고, 비어 있을 때만 `fetchGlucose(skipLocalCache: false)`로 서버 보강.

#### 중복 팝업·다른 화면에서 뜨는 현상

- (적용 후) **`_shareInFlight`** + 진행 다이얼로그로 **연속 탭·중복 share** 완화.
- 비동기 작업이 끝난 **뒤**에만 시트가 뜨므로, 그동안 사용자가 **뒤로 가기·설정 이동**을 하면 **이미 다른 화면 위에** 시트가 올라오는 식으로 보일 수 있음 — 진행 모달로 “처리 중”은 완화, OS 시트 타이밍은 여전히 **비동기 UX** 한계.

#### 플랫폼·라이브러리

- **`share_plus`**: Android/iOS 공유 시트 전환·애니메이션은 **OS·제조사** 편차가 큼. 앱 로직과 분리해 재현 캡처가 필요함.
